🚀 Enterprise Architecture Summary

NTA WebSearch API is hosted natively on your dedicated Lenovo 4GB hardware server in Termux (aarch64), executing a real headless Chromium Sandbox with Chrome DevTools Protocol (CDP) and high-speed Chrome TLS impersonation. It provides 100% drop-in compatibility with SerpAPI, completely eliminating third-party subscription costs and monthly quota exhaustion.

🔑 1. API Key Authentication

All endpoints accept your sovereign API key via either an HTTP Header or Query Parameter:

  • HTTP Header (Recommended): Authorization: Bearer nta_live_... or x-api-key: nta_live_...
  • Query Parameter: https://ntawebsearch.pages.dev/search?q=...&api_key=nta_live_...

Keys are created via POST /createapi or via the GUI on ntamediaserver.pages.dev. Keys follow the One-Time Reveal security protocol: the raw key is displayed once upon generation and stored only as a SHA-256 hash on the phone.

C. Android App (`nta-app-try1`) — Kotlin Integration

In `NetuarkAiService.kt`, query the sovereign API directly to offload heavy browser scraping from mobile battery:

suspend fun querySovereignWebSearch(query: String, apiKey: String): String = withContext(Dispatchers.IO) {
    val url = "https://ntawebsearch.pages.dev/api/search"
    val payload = JSONObject().apply {
        put("query", query)
        put("max_sources", 6)
        put("include_images", true)
    }
    
    val conn = URL(url).openConnection() as HttpURLConnection
    conn.requestMethod = "POST"
    conn.setRequestProperty("Content-Type", "application/json")
    conn.setRequestProperty("Authorization", "Bearer $apiKey")
    conn.doOutput = true
    conn.outputStream.use { it.write(payload.toString().toByteArray()) }

    if (conn.responseCode == 200) {
        val responseJson = conn.inputStream.bufferedReader().use { it.readText() }
        val data = JSONObject(responseJson)
        return@withContext data.optString("observation", "")
    }
    return@withContext ""
}

🛡️ 4. Security & Best Practices

  • Zero Data Leakage: Search queries are processed in your personal sandbox, not indexed by commercial ad trackers.
  • Automatic Failover: If the Chromium sandbox is busy rendering a complex dynamic page, queries seamlessly fallback to the sub-second Multi-Engine TLS scraper.
  • Process Supervision: Termux automatically recycles Chromium tabs after each query to keep the device RAM under 80 MB.
